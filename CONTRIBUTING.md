# Contributing

ParamEx is a Windows desktop application. This page covers the toolchain, the
checks every change must pass, and the conventions the tests enforce.
`docs/architecture.md` explains why the code is shaped the way it is.

## Toolchain

- Rust stable, `rust-version = "1.87"` or newer, `x86_64-pc-windows-msvc`.
- Windows 10 or later. The GUI tests render headlessly through wgpu, so a
  working graphics adapter (or the Windows software adapter) is required.
- PowerShell for the packaging scripts.

## Building and running

```powershell
cargo run -p paramex-gui
```

`paramex-gui` is the only runnable binary. The TLM oracle generator is a
`paramex-core` example.

## Checks

Run these from the repository root before opening a pull request. All of them
must pass.

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --no-fail-fast
cargo doc --workspace --no-deps
```

Useful subsets while iterating:

```powershell
cargo test -p paramex-core --test transfer
cargo test -p paramex-core --test tlm
cargo test -p paramex-gui --test gui_transfer
cargo test -p paramex-gui --test gui_tlm
cargo test -p paramex-gui --test gui_shared
cargo test -p paramex-gui --test app_snapshot
```

## Test data

Every committed input is synthetic and regenerable. The vocabulary:

- **fixture**: an ordinary raw test input under `tests/fixtures/`.
- **reference**: committed expected data under `tests/reference/`.
- **oracle**: expected data regenerated by an in-tree Rust generator.

Regenerate the TLM oracle corpus after a deliberate change to TLM parsing,
fitting, or CSV shape:

```powershell
cargo run -p paramex-core --example gen_tlm_corpus
```

`shared::numpy_compat` matches documented NumPy/pandas tie-breaks, rounding,
and NaN handling. Do not replace those helpers with algebraically equivalent
rewrites; add a focused reference test for any new behavior.

## Snapshots

`crates/paramex-gui/tests/app_snapshot.rs` renders the real application and
compares each scene with a baseline PNG under `crates/paramex-gui/tests/snapshots/`.
A failed comparison writes `.new.png` and `.diff.png` next to the baseline; a
missing baseline fails the test rather than creating one.

To accept an intentional pixel change:

```powershell
$env:UPDATE_SNAPSHOTS = "1"
cargo test -p paramex-gui --test app_snapshot
Remove-Item Env:UPDATE_SNAPSHOTS
```

Review the rewritten PNGs, then commit them. Never commit `.new.png`,
`.diff.png`, or `.old.png` files. Any pixel change must also keep the exact
layout and overflow guards in `gui_shared` passing and refresh both the empty
and the loaded snapshot of the affected scene.

Headless GPU renders share one wgpu device per process on Windows. Tests must
render through `common::render` and `common::snapshot` in
`crates/paramex-gui/tests/common/mod.rs`, which hold the serializing lock. A
source lint fails any test that calls `.render()` or `.snapshot()` directly.

## GUI contract

The GUI tests encode these rules; a change that violates one fails a test
rather than a review.

- The same task uses the same interaction in Transfer and TLM.
- Empty and loaded states share one render path. Loading data must not move
  fixed controls, headers, or summary columns.
- Numeric labels sit left of their inputs. Numeric fields use the shared kit:
  native single-line height, right alignment, standard compact width.
- Errors persist in the workspace and also appear in a toast.
- Only list, table, and plot bodies scroll; headers and actions stay fixed.
- Plots display `|I_D|`; signed data and exports are unchanged.
- Hand-painted controls need pointer-driven tests, not only render tests.
- Panels route widgets, text voices, colors, and shared copy through
  `ui_kit`, `theme`, and `format_ui`; the source lints reject direct egui
  styling in panel code.

## Code conventions

- Core owns scientific validation and session state; the GUI owns widget state
  and presentation. A GUI type wraps a core `Session` and delegates; it does not
  re-implement a rule.
- `paramex_core::shared` may not know about transfer curves or TLM.
- Public items in `paramex-core` are documented (`missing_docs` warns,
  `unreachable_pub` denies).
- American spelling throughout.
- Comments describe present-tense invariants and the reason for a choice. They
  do not cite files outside the repository, tickets, dates, or conversations.
- Invalid inputs, failed fits, and weak fits stay visible with a message. Never
  drop or hide an inconvenient measurement.
- The user-facing workspace names `Transfer` and `TLM` do not change.

## Technical guide equations

The in-app guide renders committed SVGs from
`crates/paramex-gui/assets/math/equations.tex`. After editing the TeX,
regenerate the SVGs with the commands in the file header and refresh the guide
snapshots. Keep `docs/technical-guide.md` in step with the same change.

## Pull requests

Keep a pull request to one concern. Describe what changed for the user, what
changed for the tests, and which snapshots were refreshed and why. Add an entry
under `Unreleased` in `CHANGELOG.md` for anything a user or a packager would
notice.
