# AGENTS.md

## Project

ParamEx is a pure Rust Windows desktop app for TFT characterization. The Cargo
workspace contains two crates:

- `paramex-core`: GUI-free Transfer, TLM, parsing, science, and export.
- `paramex-gui`: the egui/eframe desktop app and its tests.

`paramex-gui` is the only runnable binary. Do not add Python runtime or installer
requirements.

## Architecture

- Import product behavior through `paramex_core::{transfer, tlm}`.
- `paramex_core::shared` holds product-agnostic primitives (numerics, NumPy
  parity, grid ingest, file identity, CSV writing). Nothing in `shared` may
  know about transfer curves or TLM; product vocabulary lives in the product.
- Keep GUI behavior under the owning `workspaces/{transfer,tlm}` seam.
- Core owns scientific validation, session state (loaded files, settings,
  which file is selected), and state transitions; the GUI owns widget state,
  presentation, ingest effects, and recoverable pending data.
- Invalid inputs, failed fits, and weak fits remain visible. Never discard or hide
  inconvenient measurements.
- `numpy_compat` is parity-critical and requires focused reference tests.
- Comments describe present-tense invariants and the reason for a choice. They
  do not cite files outside this repository, plan or ticket identifiers, dates,
  or conversation history.

Test-data terms:

- `fixture`: an ordinary raw test input.
- `reference`: committed expected data.
- `oracle`: expected data regenerated by an in-tree Rust generator.

All committed test data must be synthetic and regenerable.

- Regenerate the TLM oracle corpus with
  `cargo run -p paramex-core --example gen_tlm_corpus`.
- Refresh GUI snapshot baselines with `UPDATE_SNAPSHOTS=1` set while running
  `cargo test -p paramex-gui`; commit the updated PNGs under
  `crates/paramex-gui/tests/snapshots/`.
- Regenerate the Technical Guide equation SVGs from
  `crates/paramex-gui/assets/math/equations.tex` (commands in its header).

## GUI Contract

- Same task, same interaction across Transfer and TLM.
- Empty and loaded states share one render path; loading data must not move fixed
  controls, headers, or summary columns.
- Numeric labels stay left of their inputs. Numeric fields use the shared UI kit,
  native single-line height, right alignment, and the standard compact width.
- Errors persist in the workspace as well as appearing in a toast.
- Only list/table/plot bodies scroll; their headers and actions stay fixed.
- Characterization plots display positive `|I_D|`; signed core data and exports
  remain unchanged.
- TLM labels the fitted intercept as `intercept (2R_c)` and the derived value as
  `R_c/contact`.
- Hand-painted controls require pointer-driven tests.
- Pixel changes require exact layout/overflow guards and refreshed empty+loaded
  snapshot pairs.

Do not rename the user-facing `Transfer` or `TLM` workspaces.

## Commands

Run from the repository root:

```powershell
cargo fmt --all --check
cargo test --workspace --no-fail-fast
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p paramex-core --test transfer
cargo test -p paramex-gui --test app_snapshot
cargo run -p paramex-gui
.\packaging\windows\build-local-dist.ps1
.\packaging\windows\test-build-local-dist-failure.ps1
```

`build-local-dist.ps1` always rebuilds the release binary, enforces the 15 MiB
size gate, and writes `target/dist/ParamEx/`. `test-build-local-dist-failure.ps1`
checks that a failed build leaves the previous distribution untouched.

## Definition Of Done

1. Formatting, full workspace tests, and Clippy pass.
2. Pixel changes pass snapshots plus exact layout and overflow guards.
3. Interactive custom widgets have a real pointer/keyboard state test.
4. Deleted or renamed files leave no stale references.
5. The packaged `ParamEx.exe` starts and stays below the 15 MiB release gate.
6. The working tree contains no `.old.png`, build output, or unrelated changes.

Do not tag or push unless the user explicitly asks.

## Release

The workspace version and `vX.Y.Z` tag must match. There is no CI publisher:
a release is cut locally by the checklist in `docs/release.md`, which runs the
gates above, packages with `build-local-dist.ps1`, and attaches the executable
to a GitHub release as `ParamEx-vX.Y.Z-windows-x64.exe`. Every user-visible
change gets an entry under `Unreleased` in `CHANGELOG.md`.
